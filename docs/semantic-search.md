# 语义检索：本地运行与边界

## 当前方案

现有 PostgreSQL + pgvector；本机 Ollama BGE-M3；语义候选与关键词排序用倒数排名融合（RRF，常数 60）。无需独立向量数据库或外部 API 密钥。词面排序仍保留，纯关键词模式不调用模型。

参考：[pgvector 官方说明](https://github.com/pgvector/pgvector)、[Ollama 嵌入接口](https://docs.ollama.com/api/embed)、[BGE-M3 模型说明与许可](https://ollama.com/library/bge-m3)。当前使用稠密向量检索，没有实现模型的多向量或稀疏检索能力。

## 安装与启用

1. 为实际运行的 PostgreSQL 安装 pgvector。macOS 的 Homebrew 安装须核对支持的 PostgreSQL 主版本；也可按官方说明固定版本源码编译，显式设置 `PG_CONFIG` 为对应数据库版本，执行 `make`、`make install`。本机已使用 PostgreSQL 17 编译安装 pgvector 0.8.7。
2. 原数据库执行 `npm run db:migrate` 后，再执行可选迁移 `npm run db:semantic`。已有表和计划不被修改。数据库用户需要创建扩展权限，也可请数据库管理员先创建 vector 扩展。
3. 启动 `ollama serve`，只监听本机；执行 `ollama pull bge-m3` 下载约 1.2 GB 模型。模型下载需要联网，检索推理使用本地模型。
4. 从 `http://127.0.0.1:11434/api/tags` 获取 `bge-m3:latest` 对应的完整 digest，在 `.env` 配置：

```dotenv
EMBEDDING_URL=http://127.0.0.1:11434
EMBEDDING_MODEL=bge-m3:latest
EMBEDDING_MODEL_DIGEST=填写实际模型的完整摘要
```

5. 执行 `npm run content:embed`。脚本按固定来源版本建库，每 8 条提交；已成功批次保留，可以续建。重复执行跳过内容摘要不变的条目。
6. 启动或重新启动应用。在 `/knowledge` 输入自己的问题，默认“智能匹配”，也可选择“仅关键词”。执行 `npm run test:search` 运行真实本地模型样例检查。

当前工作区已完成安装、模型配置，772 条短知识及完整文档的 1837 个分段均已建立索引。重启电脑后仍需启动 PostgreSQL、Ollama 和应用；模型常驻不是系统启动项。Docker 的基础 postgres 镜像未必含 vector 扩展；如用容器启用语义能力，需选择与数据库主版本兼容的 pgvector 镜像或自行安装扩展，基础关键词模式仍可照常运行。

## 数据与隔离

`knowledge_embeddings` 外键关联来源提交、章节路径和条号；保存模型标识、模型摘要、文本生成规则版本、内容 SHA-256 与向量，不复制用户账号或计划。

标题和正文建议用于生成索引，去除 HTML 注释、引用网址和来源/证据标签；原始知识与引用保留在原表，不改变发布版本。模型标识包含固定摘要与 text-v1 规则版本，调用前验证本机模型摘要一致；不同模型的数据不会混查。完整来源版本全部建好后才使用语义能力。

查询最长 500 字符，不将查询或查询向量写入数据库，不在应用日志输出描述。现阶段仅允许本机 HTTP 嵌入地址；不能直接改填外部服务地址。搜索仍用 GET 参数，因此浏览器历史、部署代理访问日志可能保留搜索描述，请避免输入个人敏感信息。

## 检索规则与回退

- 先在当前来源、主题或章节范围内做精确余弦检索，语义候选最多 40 条，再与词面候选按 RRF 合并；每页仍为 20 条。
- 当前初始语义相似度下限 0.55，由小样例检查选定，仅用于截断低相关结果，不表示正确概率。适用性需用户核对原文与来源；跨多个问题的输入可能只覆盖部分问题。
- 模型请求总超时 5 秒（含版本确认）；首次冷启动可能超时。本机建索引使用较长超时，且会预热模型，模型空闲 30 分钟后可卸载。
- 未配置、索引不完整、模型版本不一致、超时或不可用时，页面明确提示并回退关键词；空查询只浏览，不调用模型。
- 标签标明“关键词与语义均匹配”或“按语义找到的参考”，不把余弦相似度当置信度。
- 不做生成式问答、个体医疗/法律判断、自动创建任务或对话式条件追问。当前不提供行动场景功能。

当前小语料不建立近似索引；增长后根据查询计划和实测再评估索引、并发限制及服务容量。保留单库符合 KISS；派生索引可重建，原始知识不重写；客户端、索引和检索分责，符合单一职责与 DRY。

## 备份与验证

现有数据库备份会包含扩展声明与知识向量；恢复主机必须预先安装相同兼容的 pgvector 扩展文件。恢复演练新增向量与模型标识核对。也可在恢复原始内容后重新生成索引；不要手工删除原知识或源版本以清理向量。

自动化测试使用本机模拟嵌入服务验证异常和隔离，`test:search` 额外依赖真实本地模型与完整索引。当前六个样例只能做回归检查，不代表真实用户准确率；尚未做并发负载测试或大规模相关性评估。

## 完整文档补齐（2026-11-10）

`content:embed` 同时构建短知识和文档分段索引；新增 `document_embeddings` 对应完整文档的分段摘要。当前文档 293 份、1837 段，全部已索引，分段位置连续覆盖原文。模型版本、文本摘要、向量维度不匹配时不使用该索引。资料库按类型和主题取候选，每份文档只保留最相关分段用于排序，阅读仍显示全文。普通知识搜索附带专题结果，核实档案需主动在资料库选择。使用 `npm run content:audit -- --upstream --report` 核对所有正文与两类索引；报告不代表语义相关性的准确率。
