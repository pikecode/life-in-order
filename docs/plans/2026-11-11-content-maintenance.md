# 内容维护命令实施计划

目标：检查上游、生成逐文件差异报告、准备版本、确认发布、回退；普通读者无管理权限。
架构：保留不可覆盖来源版本，独立线上指针与发布审计；命令只允许人工持有数据库运维权限的环境运行，不提供公网维护 API。
技术：TypeScript、PostgreSQL 事务锁、Git 固定提交、现有导入及数据库备份。

1. 快照读取参数化，支持独立版本目录；未知章节分类、解析或许可变更停止准备，禁止静默跳过。
2. 检查命令从固定官方仓库读取 main，核对 Git blob、生成全文件新增/修改/删除及原文前后报告与摘要。
3. 准备命令幂等导入待发布版本，不复制历史行动版本或覆盖旧原文；校验数据库内容。
4. 发布/回退命令要求明确目标、预期当前版本、审核报告摘要，先备份，再事务锁内重新核对与切换，记录时间及备注。
5. 页面读取线上指针；阅读链接保留来源提交，旧版本引用不套用新条号。新文档相对链接按数据库版本解析。
6. 隔离库验证准备、拒绝未确认发布、指针并发检查、完整性拒绝及回退；更新维护说明，按低资源构建方案部署。

KISS/YAGNI 不建后台或自动发布；DRY 共享原文解析与导入，维护与渲染分责。数据与版本切换由事务保证，备份失败不发布。上游原文不执行，不自动确认内容正确性。

## 实施与验收（已完成）

- 实现维护命令、独立发布指针及事件表；准备不对前台公开，发布/回退需明确确认且先备份，冲突时事务拒绝切换。
- 30 项测试、类型检查、构建与隔离备份恢复通过；新增隔离库演练执行真实 prepare/publish/rollback 命令，验证幂等、错误摘要、内容被改写、并发预期版本及历史内容保留。
- 服务器迁移前备份为 `/var/backups/life-in-order/pre-maintenance-20261111.dump`；应用发布至 `20261111-maintenance`，使用限资源构建，旧产物保留。
- 每日检查 timer 已安装；服务器实际从 GitHub 获取 main 成功，结果与线上固定提交相同。开发机网络重试失败，已如实记录，未以失败判断无更新。
- 线上健康、首页、章节搜索、来源页与全文均通过；阅读及翻组链接带来源提交。未在生产库演练候选发布/回退，未改变线上知识版本。
- 手册：`docs/content-maintenance.md`。没有网页后台和消息提醒；管理员需查看维护日志及审核报告。
