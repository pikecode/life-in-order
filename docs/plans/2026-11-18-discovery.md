# 随便翻翻：随机内容导航

目标：保留按章阅读，增加独立随机入口，帮助没有明确目标的用户发现内容。

推荐独立板块（4 条短知识、2 篇专题）而非打乱目录；首页介绍旁提供“随便翻翻”锚点，板块位于主题目录后，不推迟既有主题首屏位置。短知识尽量来自不同主题，换组排除上一组，当前 772/9 规模在 PostgreSQL 随机抽样足够，无需推荐服务或索引改造，符合 KISS/YAGNI。

实现：共用服务端查询返回最小标题/类型/链接；首批服务端渲染，客户端仅换组按钮。GET /api/discovery 校验来源与上一组编号、只读取已公开版本，不读取核实档案/参考文件。复用现有版本链接，按需点击不计阅读。

交互：只在用户点击时更换，加载时保留原卡片，失败保留内容并可重试；不自动轮播、不保存个人兴趣、不将“随机”称为个性化推荐。

验证：数量、类型、主题分散、无重复/上一组排除、版本与输入边界；浏览器锚点/换组/失败/键盘/手机布局/进入原阅读页。类型检查、构建及限额部署，保留旧版。

实施结果：类型检查、45 项测试、本地和限额服务器构建通过；浏览器验证 320/390/768/1440px 无横向溢出，换组排重、失败保留内容、键盘焦点保留和连续点击只发一次请求。线上六张卡片、换组及专题正文跳转通过。发布 `20261118-discovery`，保留 `20261118-reading-density`；无数据库迁移、新依赖或正文变更。尚未进行大流量测试。
