# 语义检索实现计划

目标：用户用自己的话描述生活问题，检索现有知识与关联行动；保留关键词检索、两级目录和来源追溯。

架构：PostgreSQL pgvector 保存派生向量，嵌入模型生成知识与查询向量，应用融合关键词和语义排名。优先本地模型，不引入独立向量数据库、生成式回答或自动创建任务。模型运行方式等待用户选择；与之无关的数据库和查询接口先完成。

技术：现有 Next.js、TypeScript、PostgreSQL；pgvector；嵌入客户端使用原生 fetch。

1. 检查并安装匹配 PostgreSQL 17 的 pgvector；独立可选迁移，基本应用不强制依赖语义服务。
2. 新增嵌入客户端：配置、有限超时、向量格式校验；不接触用户账号或计划；模型身份隔离，避免混用不同模型向量。
3. 新增按来源版本建立索引的脚本：可重复、可续建，记录内容摘要与模型标识；索引完整后才能启用。
4. 将语义候选与现有关键词查询融合，保留主题、章节、分页；服务失败显式回退，纯关键词模式仍可选。
5. 页面增加查找方式、查找状态和匹配类型提示；展示原文与来源，不把相似度解释为正确率。
6. 测试向量异常、模型不可用、版本/主题隔离、索引幂等、混合排序与自然语言样例，并执行类型检查和生产构建。

方案比较：现有 PostgreSQL + pgvector 运维较少，符合 KISS；独立向量数据库在当前规模增加维护成本，暂缓。复用数据库来源键及查询入口符合 DRY；嵌入与检索分责，保留替换模型的明确边界；暂不做对话代理、自动生成清单或复杂近似索引，符合 YAGNI。

风险：语义相近不等于适用；需显示原始来源，低相关候选须过滤。索引随模型变更需重建，不能混用。可选迁移与失败回退保证原关键词功能可用。
