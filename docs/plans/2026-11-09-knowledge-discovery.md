# 知识发现与搜索改进

## 目标与范围

让用户从生活问题找到现有知识，再进入适用的行动清单。基于已导入的 34 章、772 条知识，不修改原始正文、来源和用户计划。

## 方案选择

1. 推荐：主题导航、明确口语别名和 PostgreSQL 参数化检索。复用数据库，无新增依赖，查询含义可解释，适合当前内容规模。
2. 后续可选：中文分词与向量语义检索。可覆盖更多自然语言，但增加服务、成本和相关性评估工作，当前不引入。

落实 KISS、YAGNI：先完成明确入口和可验证排序；DRY：查询词、高亮、摘要、分类由共享模块维护；单一职责：查询模块读库，页面负责展示。

## 已实现

- 七个主题覆盖全部章节且不重复；按上游章节归类，不代表逐条重新审核。
- 五个常见问题链接；整句别名补充明确关键词，页面公开展示扩展词。
- 空格分隔的关键词需全部命中标题或正文；整句与受控别名任一命中也可返回。
- 标题原查询匹配、标题别名匹配、标题全部词匹配、正文匹配依次排序，同分按章节及条目编号稳定排序。
- 摘要优先命中上下文，无查询时优先上游“说人话”；仅为原文截取，不生成新建议。
- 标题与摘要用 React 文本节点和 mark 高亮，禁止 HTML 注入；全文、成本收益及证据折叠阅读。
- 主题切换保留查询，分页保留主题和查询；空结果允许移除主题或清除关键词。
- 复用现有四场景关联入口，不将所有知识自动生成待办。

## 验收

单元测试覆盖主题全集、整句别名、组合词、摘要截取及特殊字符高亮；数据库测试覆盖常见问题命中、标题排序、主题限定、参数安全和旧有分页及内容不可覆盖保证；浏览器验证口语查询、主题、空结果、分页与 390 像素布局。

## 边界

别名只覆盖已维护的整句；不等于任意自然语言理解。医保等扩展词可能召回较宽，需要用户阅读摘要判断。主题按章归类，跨主题条目暂未多标签化。全表匹配适合当前小语料，数据或访问量增长后依据测量再加索引或搜索服务。

## 导航布局调整

桌面端采用左侧主题目录与右侧结果两栏，目录随页面滚动保持可见；窄屏改为顶部换行主题入口，复用同一组导航。相比各端统一顶部标签，左侧目录更适合持续浏览；相比新增抽屉，当前响应式 CSS 更简单，无额外客户端状态，符合 KISS、DRY。选中主题用 aria-current 标识，切换时保留查询。

## 两级目录（已实现）

- 七个主题下按上游原章节列出 34 个子目录，名称、数量从固定来源版本的数据库分组查询获取；数量是完整章节数量，不随关键词变化。
- 当前主题默认展开，其余折叠；原生 details 支持键盘操作。章节链接筛选范围，“查看本主题全部”移除章节限制。手机目录整体可收起，展开区限制高度并允许滚动。
- URL 增加 chapter 参数；搜索表单、分页保留主题、章节和查询。空结果可逐级放宽为主题或全库，清除关键词保留章节。
- 章节编号仅接受已有主题中的白名单，非法值忽略；合法章节与冲突主题同时出现时以章节归属为准，页面显示归一化后的主题。
- 复用既有查询的章节数组参数，不新增数据库列或依赖；KISS、DRY：不手工复制 34 个章节名称与数量。相比自建树组件，原生折叠足够满足两级目录，暂不实现条目级导航和折叠状态持久化。

## 语义检索进展（2026-11-09）

原阶段仅关键词的边界已演进：增加可选 pgvector 语义召回与关键词排名融合，纯关键词方式保留；两级目录、来源及分页保持兼容。详见 [语义检索说明](../semantic-search.md)。

## 搜索导航修复

普通 GET 表单造成整页刷新，已改用 Next.js Form 客户端导航，保留 GET 地址与无脚本提交能力；搜索时关闭自动滚动。采用官方表单和 React useFormStatus 显示等待并禁用重复提交，复用现有服务端查询，无新增查询 API，符合 KISS、DRY。延迟响应浏览器检查证明旧页面保留，关键词后退恢复与原查询能力兼容。

## 知识卡片（2026-11-10）

结果展示已演进为单列摘要卡片，原文建议优先、成本收益节选、详情按需展开。具体设计见 [知识卡片方案](2026-11-10-knowledge-cards.md)。

## 搜索范围修复（2026-11-10）

搜索提交不再隐式继承目录限制；默认全库，只有手动选择当前目录才携带主题/章节。浏览目录和分页仍保留既有范围，显式 scope 跨分页保留。草稿修改与已提交结果区分展示，应用示例明确为全库，输入关闭历史补全。
