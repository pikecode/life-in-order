# 搜索范围与历史补全修复

问题：浏览器历史补全看起来像应用推荐，但输入并不对应知识库条目；隐藏的章节条件让跨主题问题搜不到；清空输入未提交时仍显示上次结果，没有明确提示。

方案比较：保留目录内搜索并只加文字提示，改动小但仍容易误搜；采用默认全库、显式目录选择并标明已提交查询，推荐并已实现。后端筛选继续复用，不修改向量阈值来凑结果，符合 KISS、DRY、YAGNI。

改动：提取客户端 search-form.tsx，控制草稿输入和搜索范围，保留 Next Form 软导航及等待反馈。输入 autocomplete=off、type=search，无应用自造下拉候选；现有示例明确标为全库问题。显式选择当前目录时保留主题和章节，分页保留 scope；新查询默认全库。结果标题明确显示已提交查询及范围，编辑后提示下方仍是上次结果。空结果提供独立全库搜索和逐级扩大入口。

数据边界：语料为固定来源的生活建议，不能保证任意书名或任意输入有匹配。不补造推荐、不放宽阈值制造结果。浏览器或扩展可能有独立补全行为，应用不删除用户浏览历史。

验证：默认全库、手动目录、空结果扩大、查询编辑提示、分页、应用示例和 390/320 像素布局；26 项既有测试、类型检查与构建。未新增数据库或模型服务。

## 目录导航漏改修复

用户再次反馈旧词跟随目录：上一轮只调整搜索提交范围，目录链接仍调用保留 q 的地址生成函数，导致浏览目录实际仍执行搜索筛选。现已为目录单独生成地址，不携带 q/page/scope；顶部主题文字直接导航、箭头折叠，章节和全部主题均直接浏览。保留描述的扩大搜索入口仍使用原搜索地址，语义明确区分。

BrowseLink 复用 Next Link 的 onNavigate，在客户端导航时重置搜索表单；表单 onReset 同时清空受控输入与范围状态。这样再次点击同一 URL 也能清掉未提交草稿；Ctrl/Cmd 新标签打开不修改当前页输入。无需新增 API 或索引，符合 KISS、DRY；不引入全局事件或缓存破坏参数。

验证：带“鸟一样”点击 02 章显示 47 条、20 张首页卡片；点击主题显示 100 条，全库 772 条。章节跳转移除旧分页；同目录重点击清空草稿。26 项测试、类型检查及构建通过。
