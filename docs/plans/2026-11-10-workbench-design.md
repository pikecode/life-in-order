# 生活工作台视觉与阅读体验

目标：完成首页 → 搜索结果 → 阅读面板的可用样板。保留真实来源、检索结果与行动关联，形成比资料目录更鲜明、连续的体验。

已确认方向：奶白、墨黑、珊瑚橙为主，雾蓝区分知识，柔绿表达行动；以黑体取代核心页大面积衬线标题。首页有自由描述、主题入口与场景，知识列表变为短卡片，桌面右侧阅读、手机阅读层。

方案比较：原生 dialog 配合少量 React 状态，比自建弹层更容易保证焦点与 Esc；不新增弹层依赖。侧面板比每张卡片展开长正文更利于保留结果位置；本阶段不改业务架构或自动生成建议。

实现步骤：
1. 复用共享导航与搜索提交组件；首页重排为问题输入、主题入口和场景，保留真实我的计划。
2. 知识卡片缩短，主题、标题、两行建议、正文匹配线索与阅读入口保留；完整内容作为服务端子内容传入客户端面板。
3. 原生模态面板：桌面靠右、手机覆盖阅读；关闭按钮、Esc、背景关闭、焦点归还、背景滚动锁定和卸载清理；底部固定真实行动入口。
4. 独立视觉样式按核心页面作用，不修改行动编辑器；过渡 180–220ms，尊重减少动态效果。
5. 验证慢搜索不重载、目录筛选、全文与外链、连续阅读滚动与焦点、手机触控、来源为空、计划入口和登录态；执行类型检查、测试、构建。

文件：共享导航、搜索按钮、首页、知识页面和卡片；新增阅读面板客户端与核心页样式；更新相关文档。

原则：KISS 采用原生对话框；DRY 复用查询、元数据和 SSR 正文，不增加详情 API；单一职责将阅读状态与内容渲染分开；YAGNI 暂缓收藏、拖拽、推荐算法及全站计划页重做。风险是长文本阅读、手机小屏及弹层焦点，需要浏览器实测；不假定新风格能提高留存。

## 实现结果

新增 `site-header.tsx` 统一核心导航；首页提供多行描述输入、七个彩色主题入口、四场景与基于真实最近计划的继续入口。新增 `workbench.css` 作为核心页面视觉样式，移除上一阶段重复的首页与知识卡片样式。

`knowledge-card.tsx` 保留服务端渲染，缩短为主题、标题、两行建议和匹配上下文；`reader.tsx` 仅管理原生 dialog 的交互状态，服务端正文作为 children 传入，未增加详情 API。桌面靠右、手机底部阅读层；成本、收益、证据、引用和完整条目保留，真实行动入口固定底部。原生 Esc/背景关闭及焦点归还，另补 Tab/Shift+Tab 首尾循环，关闭后保持列表位置，卸载恢复滚动。减少动态效果设置关闭进入动画。

验证记录见 `../verification.md`；截图位于忽略目录 `output/playwright/`。回访用户入口用浏览器模拟 GET 响应验证，不创建真实账号或计划。未改变检索模型、数据库、计划规则，也未重做清单内部界面。

最终验收：生产包端到端流程、键盘正反向循环、焦点归还、来源和手机小屏通过，页面脚本错误为 0。撤除重复 noscript 正文以避免流式渲染兼容问题，不把局部回退视为整站无脚本支持。当前实现依赖浏览器 JavaScript，与既有客户端交互架构一致。
