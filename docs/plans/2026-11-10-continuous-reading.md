# 精简卡片与分组连续阅读

用户反馈：卡片冗余信息常驻，逐条切换操作过多。推荐每组 8 条连续向下读，组末继续；无限自动加载能进一步减少点击，但会增加位置恢复、错误重试和统计的复杂度，暂缓。

卡片默认标题与正文/摘要，仅保留一个“查看依据与原文”入口，点击后显示章节位置、成本收益、证据、来源、完整原文与署名。首页主题卡片的数量和章节移入主题目录入口，不重复常驻展示。移除多余的预览弹层，标题直接进入连续阅读。

阅读路由不变，指定条目作为本组起点，按主题内原章节顺序读 8 条；组末继续下一组，保留前一组入口和主题末尾提示。跨章在正文流内标明，不强制跳页。移除每条下一条按钮和固定底栏。保持稳定地址、刷新和后退，首条用 h1，其余 h2。来源仍能主动展开并追溯，不删除或改写知识。

分组内容在服务端生成，只读取最多 8 条正文与少量前后导航元数据；复用原来源、输入校验及 SQL 参数化。统计由 IntersectionObserver 控制，实际进入视口后才记录打开，可见聚焦停留才计时，预载八条不等于八条阅读。

KISS：有限分组和原生 details；DRY：卡片与正文共享依据组件；YAGNI：不建无限加载和兴趣算法；单一职责：批次查询、正文呈现和统计分离。无数据库迁移、新依赖或用户数据删除。

验证：批次首尾、20→27、跨章、下一组无遗漏、缺失输入；展开/折叠、向下读、手机布局、组导航、滚动恢复、屏幕外不计数、真实来源、测试、类型检查与生产构建。

完成：上述范围已实现。31 项测试、类型检查、构建及生产包浏览器验证通过，详见 verification.md。
