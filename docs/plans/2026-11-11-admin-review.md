# 网页内容管理实施计划

目标：在 https://ompeak.com/admin/ 登录后检查更新、逐文件对比、标记审阅、准备版本、确认发布和回退，并查看任务结果。

方案比较：在公开 Next 应用注入维护凭据改动少，但扩大公开应用的权限；采用独立回环 Node 管理服务（3101）和专用系统用户，通过 Nginx 的 /admin/ 代理，仅管理进程持有维护凭据。复用同一 CLI，不重复实现导入和发布规则。单账号与内存会话足够，重启后需重新登录。

步骤：
1. 增加管理员密码配置生成命令，采用 scrypt 摘要；会话 Cookie HttpOnly/Secure/SameSite，登录限速、POST 来源及 CSRF 校验、输入体积限制。
2. 增加持久化管理任务及逐文件审阅记录，维护操作串行执行，失败可查看日志；服务重启时将未完成任务明确标为中断。
3. 管理首页展示在线版本、检查结果、待审报告、准备状态、发布历史与任务。报告页按文件切换，左右完整原文对照，标记审阅、展示阻断项。
4. 发布页确认基准/目标、报告摘要、全部文件已审阅、备注，服务器重复校验；回退同样明确确认并复用自动备份。所有命令使用参数数组，不经过 shell。
5. 对会话与越权、CSRF、报告校验、审核门槛、任务状态和退出执行针对性测试；真实浏览器验证登录与审核入口，不替用户发布新内容。
6. 专用用户、最小可写目录、限资源 systemd 服务与凭据文件；Nginx 路径代理，保持普通阅读免登录；部署并交付私有初始凭据。

KISS/YAGNI 单账号、文件原文对比、不建通用 CMS；DRY 复用维护 CLI；SOLID 公开阅读、管理鉴权、后台任务分责。管理服务不可直接修改原始知识；凭据、会话、下载快照、备份均不进 Git。

- 全部 34 项测试、类型检查及隔离备份恢复通过；测试覆盖密码摘要、会话失效、限速、匿名隔离、CSRF/来源拒绝、脚本转义、审阅门槛、任务串行和重启中断。发布/回退仍沿用隔离库真实命令演练，未替用户变更线上内容。
