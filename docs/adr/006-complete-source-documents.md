# ADR-006：完整文档与派生短知识并存

状态：已实施，2026-11-10。

问题：此前章节条目解析不能覆盖 docs/ 专题、章节导读和分节说明，用户无法在站内完整阅读《结婚划不划算》。

方案一：将长文改成现有短条目，表结构少，但会损失论述、表格、内部引用及完整阅读顺序，不适合当前需求。方案二（采用）：按来源提交与路径保存完整文档，短条目仍是章节的派生阅读形式；复用 PostgreSQL、pgvector 和嵌入服务，不增加内容服务。

完整来源清单逐项标记纳入/排除、Git blob 和字节数，重建固定目录树验证不漏项。原文与分段分开，全文不被模型截断；摘要与索引可验证和重建。事务只补充缺失，不覆盖同提交已有原文；切换上游提交需显式新版本。9 篇专题进入普通阅读，244 核实档案独立归档，避免把历史待核记录当作建议。

UI 提供资料分类、全文标题目录、标准 Markdown 表格与引用；导读和来源说明用原生 details。禁止执行原始 HTML，链接限制为安全协议，已有文档引用转为本地入口。图片仅链接来源，不复制未明确许可的图片。

KISS 复用数据库和页面路由；YAGNI 不建 CMS、采集调度或账户；DRY 共享来源清单和链接；SOLID 将文件校验、事务导入、搜索与渲染分责。代价是完整章节和短条目两种形式并存，文档索引需要额外存储及构建时间。原短条目阅读统计继续有效，本轮不扩展为文档统计。

验证：文件/数据库/分段/向量全量对账、导入幂等及拒绝改写、Markdown 安全和目录测试、语义故障回退、备份恢复及真实浏览器阅读。数据同步不代表内容时效或专业适用性审核；参考文件许可按上游明确范围处理，不扩张授权。
