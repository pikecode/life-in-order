# ADR-003：单库向量检索与本地嵌入

状态：已采纳并在本地实现，2026-11-09。

背景：用户要求支持自由描述匹配知识，现有整句别名不能覆盖自然语言；当前语料为固定来源 772 条。用户采纳 PostgreSQL + pgvector 建议，模型运行方式按本地优先实施。

决策：复用 PostgreSQL，安装可选 pgvector，使用本机 Ollama BGE-M3 生成稠密向量。模型标识绑定完整摘要及文本规则版本；索引按来源隔离，外键追溯原始知识。采用精确余弦候选与关键词 RRF，不引入独立向量数据库。运行与验证见 [语义检索说明](../semantic-search.md)。

替代方案：独立向量数据库增加当前运维负担；外部模型 API 需要密钥、费用与数据传输决策，本阶段不接入。仅词面检索成本更低，保留作为用户选项和失败回退。

结果：本地检索不需要外部 API 密钥，新增模型下载、内存与模型服务运行要求；模型与索引不一致或服务失败时显式回退。基础数据库迁移不强依赖向量扩展，另用 db:semantic 启用。备份恢复目标需兼容 pgvector。语义相近不代表适用；不实现生成式判断和自动任务。

原则：KISS 保留单库与精确检索；DRY 复用来源标识与现有查询；嵌入调用和检索索引分责；YAGNI 暂缓独立搜索集群、近似索引与对话代理。

参考：[pgvector](https://github.com/pgvector/pgvector)、[Ollama 嵌入接口](https://docs.ollama.com/api/embed)、[BGE-M3](https://ollama.com/library/bge-m3)。
