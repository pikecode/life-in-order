# ADR-002：采用数据库与邮箱认证

日期：2026-11-09。状态：已采纳，依据本轮用户明确要求数据库支持并授权开发。

替代 ADR-001 中静态部署、本机作为唯一保存方式的建议；保留确定性规则、人工审阅和许可核查原则。

选择 Next.js 单体 + PostgreSQL + Better Auth 邮箱验证码。用户先预览，保存时登录，首次验证自动创建账号。认证交给成熟组件，业务接口每次校验用户归属。

替代：Supabase 托管认证与数据，集成快但平台与部署限制更多；自写验证码体系代码少但安全维护成本高，不采用。

代价：后端、邮件、数据库备份与隐私责任增加。生产上线前须完成真实邮件和备份验证。先用通用准备建议，不复制上游内容，不发布未经核查的政策结论。

KISS：单体；YAGNI：不引入缓存队列；DRY：共享规则；SOLID：模块分责。出现多人协作或复杂查询再拆任务进度表，不提前拆服务。
