# ADR-001：先以静态 Web 和确定性规则验证产品

日期：2026-11-09。状态：部分被 [ADR-002](002-database-and-auth.md) 替代；本文件保留最初提议历史。

## 背景

当前处于产品验证阶段，尚无云同步、家庭共享、自动通知和大规模内容管理的已验证需求。产品价值来自可执行且有依据的流程。

## 决策一：静态 Web，而非立即建设全栈系统

推荐手机优先的静态 Web、本机保存及文件导出。替代方案是带账号和数据库的单体系统，适合跨设备与协作成为核心需求后采用。
代价：用户清理浏览器或换设备无法自动恢复；明确告知并提供导出，不宣称有云端备份。
重新评估条件：用户频繁跨设备、需要家庭共享，或商业服务确实需要服务端记录。

## 决策二：确定性规则，而非 AI 自由生成办理流程

用审阅过的内容和明确条件生成任务。AI 问答作为后续可选入口，不作为事实源。
代价：地区和场景扩展依赖人工维护，无法立即覆盖所有问题。
重新评估条件：检索和解释确有需求，并已建立引用、拒答及质量评估机制。

## 决策三：人工选取上游内容，而非全量自动同步

逐条记录出处、版本、许可和本产品修改。替代方案是自动导入全库，但其结构和语义变化可能传播未经审阅的错误。
代价：初期覆盖有限，维护需要审阅时间。
重新评估条件：内容规模使手工维护显著阻塞，且已有稳定格式、差异检测及审阅流程。

## 原则检查

KISS：静态部署与明确规则降低复杂度；YAGNI：暂不建设账号及平台；DRY：共用内容源和任务身份；SOLID：规则、存储、展示分离。
风险：为追求最少代码把持久化与业务混在页面会破坏职责边界，应保持小模块而非引入通用框架。

本记录为设计初稿，尚未通过真实用户、团队实现能力和部署约束验证。
