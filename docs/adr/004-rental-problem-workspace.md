# ADR-004：独立退租问题处理台

日期：2026-11-10。状态：历史交互样板，保留兼容访问。当前产品已转为知识库，撤下处理台推广，详见产品需求与探索式知识库设计。

问题：现有知识目录与表单清单之间缺少连续引导，用户难以将建议变成下一步。

选择：新增独立退租页面，复用来源任务与规则；用户确认方向和条件，选择与任务进度独立存储。PlanData 的可选 workspace 字段随现有 JSONB 原子保存，不新增数据库表、任务引擎或依赖。

替代一：直接重写四场景编辑器。视觉统一，但影响所有既有计划，验证成本较高，暂缓。替代二：模型自动拆解描述并自动选任务。表达灵活，但需处理误判、隐私、服务费用和评估，目前不采用。

结果：旧清单仍可用，新安排通过首页与阅读来源进入；旧编辑器遇到新元数据会转到处理台。保留账号归属、输入校验、修订冲突与备份。KISS/DRY 复用现有规则及 API，单一职责分离交互选择与进度，YAGNI 仅实现退租样板。规模扩大到其他场景时再评估共用组件，不预建通用流程平台。
